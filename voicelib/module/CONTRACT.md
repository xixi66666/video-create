# 配音模块契约(CONTRACT v1.0)

> 定位:**视频生成流水线中的一个阶段模块**,不是一个工具、也不是一份文档。
>
> 它在「进入配音生成」时被调用,产出受本契约约束,并以**判定结果**决定流水线能否继续。
> 约束来源:`rules.yaml`(53 条)/ 结构契约:`schema/` / 解释:`SPEC.md`

---

## 0. 模块的边界定义

| | 属于模块 | 不属于模块 |
|---|---|---|
| 输入 | 可表演脚本(beats)、角色选择、档位 | 剧本创作、分镜设计、画面生成 |
| 处理 | 合成、挑条、拼接、混音、验收判定 | 视频渲染、字幕渲染、上传发布 |
| 输出 | 音频 + manifest + QC 报告 + **判定** | 成片 mp4 |
| 权力 | **可以阻断流水线** | 不能修改上游脚本内容 |

一句话:**模块是门禁,不是仆人。** 它说不过,流水线就得停。

---

## 1. 输入契约

调用方必须提供以下四项,缺一即 `E1001`。

| 项 | 形态 | 来源 | 说明 |
|---|---|---|---|
| `script` | beats YAML/JSON | 上游编剧阶段 | 必须通过 `schema/beats.schema.json` |
| `voices[]` | `{character_id, version, preset_base, refs}` | 项目 `voice.yaml` | 必须已在 `registry.json` 登记 |
| `stage` | `draft` \| `final` | 调用方决定 | 决定走草声还是终声(§3) |
| `mode` | `generate` \| `verify` \| `regenerate` | 调用方决定 | 见 §2 |

**模块不接受的东西**:一整段旁白(必须先切成 beats)、未登记的角色、没有授权的音源。

---

## 2. 三种模式

| 模式 | 何时用 | 行为 | 是否产出音频 |
|---|---|---|---|
| `generate` | 首次生成 | 全量合成 + 验收 | ✅ |
| `verify` | 已有音频,只想过检查 | 只跑规则,不合成 | ❌ |
| `regenerate` | 指定 beat 重做 | 只重录指定 beat 所在的块 | ✅ 局部 |

> `verify` 是让"约束起作用"的关键:**它允许在不重新合成的情况下,对已有产物做门禁判定**。
> 换句话,视频项目可以先跑、后补审,但**发布前必须过一次 verify**。

---

## 3. 阶段状态机

```
   ┌─────────┐  画面冻结 + 显式触发   ┌─────────┐
   │  draft  │ ─────────────────────▶ │  final  │
   │ (草声)  │                        │ (终声)  │
   └─────────┘                        └─────────┘
        │                                  │
        └── 可反复重跑,秒级                └── 锁定,任何改动=整集重录
```

**跃迁条件**(三条同时满足,缺一即 `E5006`):

1. 画面已冻结,不再改稿(L5-08)
2. 有显式授权调用(`--final-voice` 类参数,L3-06)
3. 已试听定档(L2-10)

**禁止的跃迁**:`final → draft`(降档需重新走全流程,不是状态回退)。

---

## 4. 输出契约

模块必须返回一个 `VoiceResult`,含四部分:

| 字段 | 内容 | 下游用途 |
|---|---|---|
| `verdict` | `pass` / `conditional` / `reject` | **决定流水线是否继续** |
| `manifest` | 每 beat 的音频路径、**实测时长**、哈希、`text_spans` | 时间轴、字幕 |
| `master` | 母版音频 + 规格 + 响度 | 渲染混流 |
| `qc` | 逐规则检查结果(见 `schema/qc-report.schema.json`) | 审计、返工定位 |

**给下游的最小必要信息**只有两条,其余都是审计用:

1. 每个 beat 的**实测时长**(下游据此排镜头,L5-01)
2. 每段文本的**时间区间**(下游据此出字幕,L5-02)

> 注意:输出里**不包含**"估算时长"。没实测就是没有,不许用字数推算替代(L5-06)。

---

## 5. 判定语义

| 判定 | 含义 | 调用方必须做什么 |
|---|---|---|
| `pass` | 全部 block 级规则通过 | 继续 |
| `conditional` | 仅 warn 级未过,或人工项待签 | 可继续,但记录在案;发布前必须转 `pass` |
| `reject` | 任一 block 级规则未过 | **停止**,不得继续渲染 |

**降级禁止**:不得把 `reject` 当 `conditional` 处理,也不得用"先出片再补"绕过。
与 `SPEC §2.1` 一致:失败就要中止,静音占位是最坏的失败模式。

---

## 6. 幂等与缓存

**同一个输入指纹,必须返回同一份结果,且不重复合成。**

输入指纹 = `脚本内容 + 角色版本 + 参考音频 sha1 + 预设 + 模型版本 + seed`

| 场景 | 行为 |
|---|---|
| 改了一个 beat | 只重录该 beat 所在的**块**,其余复用 |
| 改了参考音频 | 指纹全变 → 整集重录,需显式确认 |
| 重复调用同指纹 | 直接返回缓存,零成本 |
| 缓存缺失但音频文件在 | 校验哈希;不符即视为缺失(L0-11) |

> **单 beat 重录时不得自带 seed**:seed 进指纹会让整集签名漂移(见 `docs/EXTERNAL-PRACTICES.md` EP-19)。

---

## 7. 规则怎么起作用

本模块**独占执行** `rules.yaml` 的全部 53 条:

| 层 | 在模块内的角色 |
|---|---|
| L0 | 出口门禁:不过不许返回 `pass` |
| L1 | 入口校验:脚本不合规,连合成都不开始 |
| L2 | 执行参数:take 策略、seed、气口 |
| L3 | 后端适配:供应商能力、授权、缓存 |
| L4 | 后处理:混音链固定参数 |
| L5 | 交接:时长、字幕轴、失败语义 |

规则的机器可读形态见 `module/errors.yaml`,**每条 block 级规则都有对应错误码**。

## 8. 版本与兼容

| 版本号 | 含义 | 谁管 |
|---|---|---|
| `contract` | 本契约(输入输出形态) | 模块 |
| `rules_version` | 规则集(`rules.yaml` 的 version) | 规范 |
| `voice_card.version` | 角色声卡 | 声库 |

**兼容规则**:

- `contract` 升 MAJOR → 调用方必须改
- `rules_version` 升 MINOR → 可能新增规则,调用方**不需要**改,但判定可能变严
- `voice_card` 升 MAJOR → 音色变化,需重新整集合成

> 调用方锁 `contract` 的 MAJOR,不要锁 MINOR —— 否则规则收紧时你会被卡在旧版本。

---

## 9. 三条例外

规范的强制力有边界,以下情况允许走例外流程,但**必须留痕**:

| 情况 | 处理 |
|---|---|
| 供应商能力缺失(如无 `text_spans`) | 判 `conditional`,字幕轴改用强制对齐模型 |
| 参考音频暂时拿不到(试水项目) | 只允许 `draft`,禁止进 `final` |
| 规则与题材冲突 | 改规则,不要在项目里打补丁 —— 打补丁=规范失效 |
