# 配音规范 SPEC v0.2.1

> **适用范围**:本项目所有配音产出(旁白 / 角色对白)。任何一次配音构建必须通过 §2 的 L0 门禁,未通过不得进入渲染环节。
>
> **强制力**:文档 + 校验脚本。每条约束带编号(`L0-01`、`L1-03`…),校验脚本以编号作为错误码。
> 标 `[自动]` 的由脚本判定;标 `[人工]` 的需人工签收,并在挑条记录中留痕(格式见 §4.2)。

## 1. 总则

### 1.1 四条铁律

1. **单一真相源**:项目只读引用声库,禁止复制资产到项目内。
2. **ID 即契约**:`character_id` 全局唯一且永不复用;升级走 `version`,不改 ID。
3. **未登记即不存在**:角色登记表(由声库目录扫描生成)中不存在的角色,构建直接失败。
4. **无授权不合成**:`source.license_ref` 指向的授权文件缺失或过期,构建直接失败。

### 1.2 术语

| 术语 | 含义 |
|---|---|
| **beat(表演单元)** | 一次合成的最小单位,通常是一句话。不是"一段旁白" |
| **take** | 同一 beat 的一次合成尝试。规范要求 ≥3 条 |
| **preset(预设)** | 情绪 + 语速 + 停顿的参数组合,属于角色声库 |
| **干声(dry)** | 无 BGM、无混响、无压缩的原始人声,参考音频必须是干声 |
| **母版(master)** | 统一混音后的成品音轨 |

### 1.3 库内语义 vs 供应商语义

**库内只使用直觉语义,由适配器负责转换。** 这是为了隔离供应商的反直觉参数:

| 库内字段 | 语义 | 供应商差异示例 |
|---|---|---|
| `rate` | **>1 更快,<1 更慢** | IndexTTS-2.5 的 `speed` 是 **<1 更快**,必须由适配器取倒数 |
| `emo` | 具名情绪键 `{calm: 0.6}` | 供应商要 8 维定序向量,由适配器映射 |
| `pause_after` | 该 beat 后的静音秒数 | 供应商无此参数,由合成后拼接实现 |

> 违背此条会让同一份 + 预设在不同供应商上呈现相反效果,属严重缺陷。

## 2. L0 验收与门禁(最高优先级)

L0 是唯一决定"能不能发"的一层。其余六层都是为满足 L0 服务。

| 编号 | 指标 | 阈值 | 测量方法 | 类型 |
|---|---|---|---|---|
| L0-01 | 综合响度 | **-14 ± 1 LUFS** | `ffmpeg -af loudnorm=print_format=json` 两遍法 | 自动 |
| L0-02 | 真峰值 | **≤ -1.0 dBTP** | loudnorm 输出的 `output_tp` | 自动 |
| L0-03 | 静音比 | **< 8%** | 统计帧能量 < -50dBFS 的时长占比 | 自动 |
| L0-04 | 语速 | 按 `pace_profile` 分档:**drama 3.2–3.8 字/秒** / explainer 4.0–4.4 | 去标点字数 ÷ 有声时长(非总时长) | 自动 |
| L0-05 | 源采样率 | **≥ 22050 Hz** | `ffprobe` | 自动 |
| L0-06 | 母版采样率 | **48000 Hz** | `ffprobe` | 自动 |
| L0-07 | BGM 避让深度 | **≥ 10 dB** | 人声段与非人声段 BGM 包络差 | 自动 |
| L0-08 | 声画对齐 | **误差 < 0.2 s** | 音频末点 vs 镜头末点 | 自动 |
| L0-09 | 音色一致性 | **声纹余弦 ≥ 0.85** | CAMPPlus / 同角色跨集比对 | 自动 |
| L0-10 | 每 beat take 数 | **≥ 3** | 读挑条记录(§4.2) | 自动 |
| L0-11 | 交付物自洽 | manifest 句数 = 脚本 beat 数,且逐句哈希可核 | 读 manifest + 复算哈希 | 自动 |

### 2.1 两条硬性禁令

- **禁止静音占位。** 合成失败必须中止构建并报错。用静音/空白音频"兜底"会让缺陷流入成片,是最坏的失败模式。
- **禁止有损中转。** 合成输出到混音之间不得经过 MP3/AAC。上游给 MP3 就在 L3 判不合格,要求 WAV/PCM。

### 2.2 交付前 checklist(人工)

- [ ] 通听一遍,无读音错误(多音字、专名、数字)
- [ ] 情绪与画面情绪一致
- [ ] 句间气口不机械(不是每句都等长停顿)
- [ ] 与 BGM 不打架,人声清晰
- [ ] 无爆音、无齿音刺耳、无底噪

---

### 2.3 两档配音(强制)

配音分两档,**不得混用**:

| 档 | 引擎 | 使用时机 | 成本 |
|---|---|---|---|
| **草声 draft** | edge-tts / 轻量供应商 | 写稿 → 校验 → 分镜 → 粗剪 → 评审的**全流程** | 秒级、免费、免参考音频 |
| **终声 final** | IndexTTS-2.5 + 角色参考音频 | 角色冻结 + 画面冻结后,**显式触发** | 分钟~小时级 |

三条纪律:

1. **草声不得作为交付音色**(L3-09)。它只用来验证"节奏对不对",不用来判断"好不好听"。
2. **升终声必须显式授权**(L3-06),且必须在画面冻结之后(L5-08)。
3. **首轮终声完成后回写实测语速**(L0-04),下一集按实测口径写稿。

> 为什么必须分档:改一句台词就等整集克隆重合成,是当前最大的返工来源。
> 草声把"验证流程"的成本压到秒级,把"音质"成本推迟到定稿之后。

## 3. L1 脚本层:可表演脚本

### 3.1 结构

配音输入不是一段文章,是 `beats` 列表:

```yaml
scene_id: S01
beats:
  - id: S01-B01
    speaker: demo_qingleng_female
    text: "雨夜。"
    emotion: calm
    intensity: 0.3
    pause_after: 0.4
    notes: "低声,近乎自语"
```

| 编号 | 约束 | 类型 |
|---|---|---|
| L1-01 | 每个 beat 必须有 `speaker` / `text` / `emotion` | 自动(schema) |
| L1-02 | `text` 去标点后 **≤ 18 字**;超长必须切分 | 自动 |
| L1-03 | **禁止整段旁白**:任一 beat 超过 40 字或含 ≥3 个句号,判违规 | 自动 |
| L1-04 | 标点原样保留,不得被 LLM 改写为无标点长句 | 自动 |
| L1-05 | `emotion` 必须来自该角色预设表中已定义的键(见 §4.4) | 自动 |
| L1-06 | **合成块** ≤ 40 字(块是缓存单位,可含多个 beat);超长按语义边界切 | 自动 |

### 3.2 标点 → 韵律映射表

标点是免费的韵律控制器。合成前由 L1 把标点转成参数,不要让 TTS 自己猜。

| 标点 | 处理后停顿 | 韵律提示 |
|---|---|---|
| `,` | 0.18 s | 轻提,不停气 |
| `。` | 0.35 s | 句尾下沉 |
| `?` | 0.30 s | 尾音上扬 |
| `!` | 0.25 s | 重音前置 |
| `……` | 0.60 s | 拖音 + 气口 |
| `——` | 0.25 s | 顿住,后接重音 |
| `、` | 0.10 s | 并列快走 |

### 3.3 口语化改写规则

书面语直接送 TTS 是 AI 感的主要来源之一。改写要求:

- 去掉 `可` `乃是` `遂` 等文言连词
- 长定语拆短句
- 允许出现语气词(`罢了` `罢了` 类)、半截话、重复起头
- 数字写成汉字(`第三集` 不写 `第3集`),除非该角色设定为播报腔

## 4. L2 表演层:指令与 take

| 编号 | 约束 | 类型 |
|---|---|---|
| L2-01 | 每个 beat **≥3 take**,参数差异化(至少 rate / emo 各变一档) | 自动 |
| L2-02 | `emo` 各键之和 **≤ 0.8**(留余量给音色自带的情绪底色) | 自动 |
| L2-03 | 气口密度:每 **2–3 个 beat** 插一次呼吸,增益 **-22 dB** | 半自动 |
| L2-04 | 句间停顿须有变化,允许值 0.15–0.6 s,禁止全部同值 | 自动 |
| L2-05 | take 选定需记录理由,从下列枚举中选 | 人工 |

### 4.1 take 挑选规则(按优先级)

1. **无读音错误**(最高优先级,一票否决)
2. 情绪命中:听感与 `emotion` 一致
3. 气口自然:换气位置符合语义,不切在词中
4. 音色一致:与同角色历史样本无明显漂移
5. 起收干净:句首无杂音,句尾不突兀截断

### 4.2 take 记录格式

```yaml
# 挑条记录:每个 beat 一条
- beat: S01-B01
  chosen: 2
  candidates: 3
  params: {rate: 0.95, emo: {calm: 0.6, melancholic: 0.15}}
  rejected: {1: "句尾截断", 3: "气口错位"}
  reviewer: 人工
  reason: 情绪命中
```

> **为什么必须留痕**:三个月后你要复现某一句,只有这条记录能告诉你当时为什么选它。

### 4.3 参考音频即表演基线

零样本克隆会把参考音频的**语速与语调一并克隆**。因此:

- 参考音频必须是**目标角色的说话方式**,不能是"标准普通话朗读"
- `presets` 只能在这个基线上微调,无法反向纠正基线
- 选中一条错误基线的参考音频,后续所有情绪调整都是失效的

| 编号 | 约束 | 类型 |
|---|---|---|
| L2-06 | 参考音频 **10–14 秒**(硬上限 15 秒,超出会被上游静默截断) | 自动 |
| L2-07 | 参考音频的语速须落在该角色目标区间内(与 L0-04 同口径) | 人工 |
| L2-08 | 同一 beat 的 3 个 take 必须**固定 seed** 并记入 `take_log`;不固定 seed 得到的差异是采样噪声,不算差异化 take | 自动 |
| L2-09 | 参考音频须登记 **sha1 指纹**;指纹与清单不符即拒绝合成 | 自动 |
| L2-10 | 升终声前必须完成**试听定档**(选定 preset + 参考音频),定档后才可整批合成 | 人工 |

---

### 4.4 预设表(数据契约)

每个角色维护一张预设表,表的键即 `emotion` 的合法取值。每档包含:

| 字段 | 含义 | 取值 |
|---|---|---|
| `rate` | 语速 | 0.7–1.3,**>1 更快** |
| `emo` | 情绪权重,具名键 | 见下,各键之和 ≤0.8 |
| `intensity` | 表演强度 | 0–1 |
| `pause_after` | 该 beat 后的静音 | 0–1.5 s |
| `gain_db` | 增益补偿 | -12 ~ +6 dB |
| `reverb` | 混响档 | `none` / `close` / `room_small` / `room_large` |

情绪键固定为 8 个:**happy / angry / sad / afraid / disgusted / melancholic / surprised / calm**。

> **为什么用具名键而不是定序数组**:供应商要的是 8 维定序向量,数组写错一位从文本上看不出来;
> 具名键写错立刻能被校验拦住,映射由适配器负责(§1.3)。

## 5. L3 声码器层:能力矩阵与适配器

### 5.1 能力矩阵

每个供应商用一张**能力登记表**描述,只登记能力,不写死调用方式。字段如下:

| 字段 | 含义 |
|---|---|
| `clone` | 零样本克隆,需参考音频 |
| `instructions` | 支持自然语言表演指令 |
| `emotion_vector` | 支持情绪向量 / 具名情绪 |
| `rate_control` | 支持语速参数 |
| `duration_control` | 支持目标时长精确控制 |
| `stream_text` | 流式返回时附带文本(可做字幕轴) |
| `sample_rate` | 原生输出采样率 |
| `max_chars` | 单次合成字数上限 |
| `license` | 许可类型,含商用限制 |
| `thread_safe` | 是否可并发调用 |

### 5.2 适配器契约

每个供应商一个适配器,必须实现:

```
synthesize(beat, preset, refs) -> { audio_path, sample_rate, text_spans, duration }
```

| 编号 | 约束 | 类型 |
|---|---|---|
| L3-01 | 输出必须是无损 WAV/PCM,**≥22050 Hz** | 自动 |
| L3-02 | 适配器负责库内 `rate` → 供应商语义的转换 | 自动(单测) |
| L3-03 | 适配器负责 `emo` 具名键 → 供应商格式的映射 | 自动(单测) |
| L3-04 | 支持 `stream_text` 的供应商必须回传 `text_spans`(供字幕对齐) | 自动 |
| L3-05 | `thread_safe=false` 的供应商必须走串行队列,禁止并发 | 自动 |
| L3-06 | 克隆重配必须带**具名授权参数**(如 `--final-voice`),缺失即硬失败;脚本与 agent 均不得自动补 | 自动 |
| L3-07 | 端点、存储根、交付根等**机器属性只走环境变量**,禁止写入声卡或任何库文件 | 自动 |
| L3-08 | 推理服务**按需启停、用完即关、不预启动**;不得常驻占显存 | 人工 + 脚本 |
| L3-09 | 草声档可用于全流程与评审,**不得作为交付音色** | 自动 |
| L3-10 | 缓存摘要须覆盖 文本 + 参数 + 模型版本 + seed;改一句只重录所在块;**失败段不得用旧段补齐** | 自动 |

### 5.3 许可红线

- 使用前必须确认供应商许可是否允许**商用**、是否要求署名、是否限制生成内容用途。
- `license` 字段为 `unknown` 的供应商,**禁止用于会发布的项目**。
- 例:IndexTTS-2.5 使用 Bilibili Model Use License(非 Apache 2.0),商用条款需逐条确认后填入。

### 5.4 供应商与音色对比方法学

换供应商、换模型、换参考音频时,必须按下列方法对比,**否则结论无效**:

1. 所有供应商共用**同一段**参考音频,参考音频的转写必须精确对应
2. 另选 **≥3 段未参与克隆的原声**,覆盖专名、口语问句、句尾节奏;用同一文案合成
3. 至少再生成一轮,**保留全部结果**,不许只挑最好的一次
4. 试听副本只做**恒定增益 + 限峰**,不改速度/音高、不加压缩——消除响度偏好
5. 隐藏供应商名称给听者选,并如实记录是否已揭晓
6. ASR 只作辅助排查;**原声也要跑同一 ASR 作对照**,不得用 ASR 结果覆盖原稿
7. 声纹模型须与**同文案的未见原声**比较,至少两种独立编码器,并报告**原声之间的基准分数**
8. **余弦不是校准概率**;分数接近时不得宣称胜负
9. 听感与模型分数不一致时**如实保留**,两者衡量的不是同一件事
10. 单人偏好测试**不得写成双盲实验**

## 6. L4 混音层:固定后处理链

参数固定如下,**禁止在项目内覆写**,以保证跨项目听感一致。

| 环节 | 固定参数 |
|---|---|
| 高通 | 80 Hz,二级 |
| EQ | +2.0 dB @ 3 kHz(Q 0.9);-1.5 dB @ 250 Hz(Q 1.2) |
| 去齿音 | 6–8 kHz,压 -3.0 dB |
| 压缩 | 3:1,阈值 -18 dB,attack 5 ms,release 80 ms,knee 6 dB |
| 混响 | plate,decay 1.0 s,wet -18 dB |
| 限幅 | 天花板 -1.0 dBTP |
| BGM 避让 | sidechain 深度 -12 dB(合格线 ≥10 dB),attack 15 ms,release 250 ms |
| 环境声 | 增益 -20 dB(±3),立体声宽度 0.8 |
| 母版 | 48 kHz / 24 bit,-14 LUFS |

### 6.1 处理顺序(不可调换)

```
升采样 48k
  → 高通 80 Hz
  → EQ(+2dB @3k 提清晰 / -1.5dB @250Hz 去浑)
  → 去齿音 6–8k
  → 压缩 3:1(阈值 -18dB,attack 5ms,release 80ms)
  → 轻混响(plate 1.0s,wet -18dB)
  → 限幅 -1.0 dBTP
  → BGM sidechain ducking
  → 环境声层叠加
  → 响度归一到 -14 LUFS
```

| 编号 | 约束 | 类型 |
|---|---|---|
| L4-01 | 人声链参数只能取 §6 的固定值 | 自动 |
| L4-02 | BGM 必须用 sidechain ducking,**禁止用固定音量硬叠** | 自动(L0-07 联动) |
| L4-03 | 环境声层常驻,增益 -20 ± 3 dB | 自动 |
| L4-04 | 人声必须居中;BGM / 环境声可铺立体声,三者不得同平面 | 人工 |
| L4-05 | 混响 wet 不得高于 -12 dB(超过则"浴室感") | 自动 |
| L4-06 | 母版输出 48 kHz / 24 bit 或以上 | 自动 |
| L4-07 | 源为 22.05 kHz 时必须**先升采样到 48 kHz 再处理**,禁止在源采样率上做 EQ/压缩 | 自动 |
| L4-08 | 审片/试听副本只做恒定增益与限峰,不做任何音色处理 | 人工 |

> **为什么混音层最值钱**:专业配音感的 80% 来自这里,而不是模型。裸干声直接叠 BGM,一定"塑料"。

## 7. L5 流程层:音频驱动画面

### 7.1 时序(强制)

```
脚本 beats → 合成 → 量出每 beat 真实时长 → 计算镜头时长 → 字幕轴 → 渲染
```

**禁止先定镜头时长再塞音频。** 顺序反了必然声画错位。

| 编号 | 约束 | 类型 |
|---|---|---|
| L5-01 | 镜头时长 = 所属 beats 音频时长之和 + 留白,不得先验写死 | 自动 |
| L5-02 | 字幕时间轴必须来自音频 `text_spans`,禁止按时长均分 | 自动 |
| L5-03 | 声画对齐误差 < 0.2 s(L0-08) | 自动 |
| L5-04 | 任一 beat 合成失败即中止整个构建,不得降级输出 | 自动 |
| L5-05 | manifest 是**派生物**:句数 = beat 数,`durationSec` 一律为实测值,禁止手改 | 自动 |
| L5-06 | 时间轴必须来自写入的采样帧/实测时长,**禁止按字数占比分摊** | 自动 |
| L5-07 | 失败段阻止拼接,禁止用旧段或静音补齐 | 自动 |
| L5-08 | 升终声前画面必须冻结;升档只换音轨,下游音轨/字幕全量重推 | 人工 + 自动 |

### 7.2 失败处理

| 情况 | 正确做法 | 禁止做法 |
|---|---|---|
| TTS 接口报错 | 中止,报错码 L5-04 | 写静音音频继续 |
| 采样率不达标 | 换供应商 fallback_order 下一位 | 直接使用 |
| 超长 beat | 回 L1 切分 | 自动加速蒙混 |

## 8. Windows / CUDA 适配差异

> v0.2 的参考实践全部以 **macOS / MPS** 为基线,直接照抄会失败。本章列出强制差异。

### 8.1 平台基线

- **主方案:Windows 原生 + NVIDIA CUDA**(2026-11-10 已定),不引入 WSL2 / Docker
- **兜底**:仅当原生安装在某依赖上失败才切 WSL2,不得作为默认前提
- 注意力后端固定 `sdpa`;`flash-attn` 在 Windows 无预编译轮子,不启用

### 8.2 文本归一化(最容易踩)

`pynini` 在 PyPI 上只有 Linux x86_64 wheel,`nemo-text-processing` 因此无法直接装;conda-forge 是否有 win-64 构建**需实测**。

| 方案 | 代价 | 定位 |
|---|---|---|
| **预归一化**:送模型前把数字、时间、单位改写成汉字 | 需维护少量规则;与 L1-03 本就要求一致 | **主方案** |
| conda 装 `pynini` + `WeTextProcessing` | win-64 轮子不保证存在 | 可选增强 |
| 推理跑 WSL2 / Docker | 维护两套环境 | 仅兜底 |

> 关键事实:**缺归一化时模型仍能跑**,只是数字读得差。所以这不是阻塞项——别为一个可选增强卡住整条线。

### 8.3 显存与并发

| 项 | macOS/MPS 基线 | Windows/CUDA 实际 |
|---|---|---|
| 显存水位 | `--mps-mem-limit-gib` / `iogpu.wired_limit_mb` | `nvidia-smi` 观测;设 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` |
| 束宽代价 | 近乎免费(1→3 束仅 +4%) | **近线性**,3 束 ≈ 3 倍耗时 → 试听用 1 束,批量才用 3 |
| 并发 | 单 worker 串行 | 同样串行;Windows 无 fork 优势,用队列不要多进程 |
| 冷启动 | 1–2 分钟 | 含 CUDA 上下文,通常更久 |

### 8.4 服务生命周期命令对照

| 动作 | macOS | Windows |
|---|---|---|
| 判端口占用 | `lsof -nP -iTCP:8766 -sTCP=ESTABLISHED` | `Get-NetTCPConnection -LocalPort 8766 -State Established` |
| 找监听 PID | `lsof -ti tcp:8766 -sTCP=LISTEN` | `(Get-NetTCPConnection -LocalPort 8766 -State Listen).OwningProcess` |
| 关闭 | `kill <pid>` | `Stop-Process -Id <pid>` |
| **禁止** | `pkill -f vibe_tts_server.py` | `taskkill /F /IM python.exe`(会杀光所有 Python 进程) |

### 8.5 路径与编码

- 盘符 + 空格 + 中文路径会炸 ffmpeg 滤镜;**工程根用 ASCII 短路径**
- `subtitles` 滤镜里盘符冒号需转义(`D\:`),旧管线已踩过
- 开启长路径支持,或把工作根压到 3 层以内(<260 字符)
- 强制 UTF-8:`PYTHONUTF8=1`、`chcp 65001`;否则中文文本与文件名乱码

### 8.6 音频

- IndexTTS 原生 22.05 kHz → **先升采样到 48 kHz 再混**(L4-07)
- 不要试图实时监听合成结果,一律落盘再听
- `loudnorm` 两遍法与 `sidechaincompress` 在 Windows 版 ffmpeg 上均可用

### 8.7 与参考实践的对应关系

| 参考做法(macOS) | Windows 改法 |
|---|---|
| `uv run --no-project` | 可用,确保 uv 在 PATH |
| `ln -s` 挂 skill | 用 junction(`mklink /J`)或直接复制;符号链接需管理员权限 |
| `sed -i ''` | 用 PowerShell 或 Python 改写 |
| `nohup` 长跑 | 用后台作业/任务计划,不要 nohup |

**YAML 书写约定(踩过的坑,写死):**

| 约定 | 原因 |
|---|---|
| 日期一律加引号 `"2029-11-30"` | 不加引号会被 YAML 解析成 date 对象,消费方拿到非字符串 |
| 形如 `18-22` 的区间也加引号 | 同上,避免被误读 |
| 版本号 `0.1.0` 加引号 | 不加会被当成数字或字符串歧义 |
| 中文冒号后留一个空格 | 避免 `key:值` 解析失败 |
