# 采集:从视频到角色

> 操作台「采集」页的说明。目标:给一个链接,**自动截出可用的人声片段**,再变成声库里的角色。

## 流程

```
① 下载 / 读本地文件  (yt-dlp)
② 抽音轨            (ffmpeg → 44.1kHz 单声道 WAV)
③ 人声分离          (Demucs,去 BGM 与环境声)
④ VAD 切段          (能量阈值,20ms 帧)
⑤ 择优窗口          (每段取能量最高的 12 秒)
⑥ 打分              (时长/峰值/削波/静音/起伏)
⑦ 你试听挑一段 → 写入 refs/<kind>.wav + 记录来源
```

### 两个必须知道的坑

**坑 1:demucs 从 HuggingFace 拉权重,直连不通**
`huggingface.co` 在国内基本不可达,会导致分离阶段**无限等待**(看起来像卡死)。
代码里已默认注入 `HF_ENDPOINT=https://hf-mirror.com`;手动跑 demucs 时要自己设。

**坑 2:权重首次下载 80 MB**
走镜像很快(实测秒级,已缓存),之后离线可用。缓存位置 `~\.cache\huggingface\hub`。

## 性能实测(CPU)

| 素材 | 音频时长 | 分离耗时 | 倍速 |
|---|---|---|---|
| 3 分 32 秒 B 站视频 | 212 s | 约 180 s | **0.85×** |

即 3 分钟视频约 3 分钟分离。有 GPU 时会快 5–10 倍,但当前环境没有可用 CUDA。

## 平台差异

| 平台 | 情况 |
|---|---|
| B 站 / YouTube | yt-dlp 支持最好,通常直接可用 |
| 抖音 / 快手 | 多数需要登录 → 填 `cookies.txt` 路径 |
| 小红书 | 反爬强,经常失败,不建议 |
| 本地文件 | 直接填路径,最稳(自己的素材首选) |

`cookies.txt` 用浏览器插件导出即可,**只放本机,不要提交进仓库**。

## 评分怎么看

| 字段 | 含义 | 合格线 |
|---|---|---|
| 时长 | 片段长度 | 10–14 秒;>15 秒硬上限 |
| 峰值 | 最大电平 | -3 ~ -12 dBFS |
| 削波 | 超过 0.985 满刻度的比例 | < 0.2% |
| 静音 | 片段内静音占比 | < 20% |
| 音量起伏 | 帧 RMS 的相对标准差 | < 1.5(过大可能多人交替) |
| 评分 | 综合 0–100 | **≥70 值得试听** |

**「音量起伏大」只是启发式**,不是说话人分离模型。判断有没有多人,靠你自己听。

## 三条必须知道的限制

**1. BGM 会污染音色**
没分离的片段,模型会把伴奏当成嗓音特征学进去。所以 Demucs 不是可选项——除非素材本来就干净。

**2. 从别人视频里截声音,需要授权**
平台条款通常禁止抓取,声音本身也受权利人控制。采集器会自动生成 `licenses/<id>.md` 记录来源,
但那只是**证据,不是授权**。没有书面授权,角色只能停在 `draft`。

**3. 产出是"能用的音色",不是"高质量声库"**
真实片段常有混响、被压过码率、情绪单一。采集器能淘汰明显不合格的,但**替代不了让 CV 录 30 秒**。
把它当"快速试水",不要当"最终音色"。

## 故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| 下载失败 | 需登录 / 地区限制 | 填 cookies.txt;换 B 站源 |
| 检出 0 段 | 全片是 BGM;或音量过低 | 开分离;或换更长的素材 |
| 候选全是"未分离" | 没装 demucs | `pip install -U demucs` |
| 分离太久 | CPU 模式 | 正常;3 分钟素材约 2–5 分钟 |
| 全部候选评分低 | 素材本身差 | 换素材,别硬用 |
