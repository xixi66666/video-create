# 外部实践吸收清单

> 版本 v1.0 · 调研日期 2026-11-09 · 对应 SPEC v0.2
> 目的:把外部成熟项目的做法逐条过一遍,判定 `采纳 / 改写 / 不采纳` 并给理由,而不是整体照搬或整体无视。

## 一、调研对象

| 来源 | 定位 | 与我们的关系 |
|---|---|---|
| [ThreeFish-AI/vibe-video](https://github.com/ThreeFish-AI/vibe-video) | 十阶段科普视频流水线,MIT,**真用 IndexTTS-2.5** | 配音生命周期、门禁设计、服务运维 |
| [NanmiCoder/creator-pipeline](https://github.com/NanmiCoder/creator-pipeline) | 配音 skill 集,含 voice-clone-tts | 分段、缓存、验证、供应商对比方法学 |
| [UnderleveledBuilder/awesome-short-drama-skills](https://github.com/UnderleveledBuilder/awesome-short-drama-skills) | 83 个短剧/漫剧 skill 的目录 | 生态盘点,**无音频类目**这一事实本身是结论 |

**判定原则**(先定标准,再判条目,避免拍脑袋):

1. 能减少「翻车但不可见」的 → **采纳**
2. 原理对但与「自建漫剧角色声库」目标冲突 → **改写**
3. 绑定其技术栈/平台(macOS、Remotion、特定供应商) → **不采纳**,只记原则
4. 增加无法验证的复杂度 → **不采纳**

## 三、四处正面冲突与裁决

### 冲突 1:声音样本「不入库」 vs 我们要「建声库」

vibe-video 的立场:**声音样本是生物特征,不入库,`refs.toml` 只存指纹,试听后即删**。

裁决:**改写**。它的场景是"通用视频产品,用户是外部人",合规门槛最高。我们是自建角色库,参考音频本身就是核心资产,不存等于没有声库。

折中方案:
- 参考音频存**私有目录**,不进公开仓库(`.gitignore`)
- 入库的是**指纹 + 元数据**,不是音频字节
- 授权文件必须先于音频存在(铁律 4)
- 目录访问受控,导出/分享需显式操作

### 冲突 2:语速 254 字/分(=4.23 字/秒) vs 我们的 3.2–3.8 字/秒

vibe-video 的 `story` 档按 **254 字/分钟** 写稿预算,是他唯一有整集实测的档位。我们的 L0-04 定的是 3.2–3.8 字/秒(192–228 字/分)。

裁决:**两者都对,但必须按题材分档**。科普解说要快,国风漫剧旁白要慢。故 v0.2 引入 `pace_profile`:

| 档 | 字/秒 | 字/分 | 适用 |
|---|---|---|---|
| `drama` | 3.2–3.8 | 192–228 | 漫剧旁白、对白(默认) |
| `explainer` | 4.0–4.4 | 240–264 | 解说、口播 |

**并且**引入 EP-09 的实测校准:首轮生成后按实测值回写本角色/本题材的口径,不靠拍脑袋。

### 冲突 3:单句 18 字 vs 40 字

我们 L1-02 定单句 ≤18 字;creator-pipeline 分段 `--max-chars 40`。

裁决:**不冲突,量纲不同**。18 字是**表演单元(beat)**的上限,40 字是**合成块(缓存单位)**的上限。一个块可含多个 beat。v0.2 把两者分别写明(L1-02 / L1-06)。

### 冲突 4:三仓库都没有「漫剧配音规范」

`awesome-short-drama-skills` 收录 83 个短剧 skill,分类为「全流程 / 编剧 / 分镜视觉 / 上游 / 基本功 / 去AI味」——**没有音频类目**。vibe-video 与 creator-pipeline 都只做「科普视频 / 口播配音」。

裁决:**确认自建是必要的,不是重复劳动**。但要吸收执行层的成熟机制,而不是另起一套。

## 四、本次调研修正的错误

| 项 | v0.1 写的 | 实际 | 影响 |
|---|---|---|---|
| 参考音频时长 | 3–8 秒 | **10–14 秒**,硬上限 15 秒 | 素材录制白做,且超 15 秒被静默截断 |
| 音色一致性指标 | 余弦 ≥0.85 | 单值不足以判定,需双编码器 + 原声基准 | 可能用一个漂亮数字骗过自己 |
| 可复现性 | 未定义 | 上游无种子,必须显式固定 | 3-take 可能只是采样噪声 |
| 语速 | 单一区间 | 需按题材分档 + 实测校准 | 古风旁白被逼成播报腔 |

## 六、已安装的 skill

| 项 | 值 |
|---|---|
| 路径 | `D:\Code\video\skills\awesome-short-drama-skills` |
| 本体 | `skills/short-drama-skill-finder/SKILL.md` |
| 数据 | `data/skill_index.json`(90+ 项目结构化数据)、`data/skills.toml`、`data/taxonomy.toml` |
| 体积 | 1.14 MB(24 个文件) |
| 安装方式 | 仓库整包 40 MB+(含 `web/` 站点与 `evals/` 图片),按需只取 `skills/ data/ scripts/ templates/` |

**它是什么**:一个**选型推荐器**,不是配音工具。输入「我在做漫剧 / 卡在分镜 / 用 Seedance / 用 Codex」,它从清单里返回 3–5 个 skill + 安装命令 + 许可证。

**它对我们有什么用**:
- 作为**生态地图**,判断"要不要自己写"——已证实:90+ 项目里**没有音频/配音类目**
- 它的 `data/skill_index.json` 含 stars / license / 最后更新 / 支持平台,可作为供应链评估输入

**注意事项**:
- 原 skill 默认从 `https://shortdramaskills.com/data.json` 取数据,该域名在本机网络下大概率不通;本地 `data/` 已有打包数据可替代
- 它会提示"安装前先读 SKILL.md,不要擅自执行安装命令"——这条我们照做
