# 作品与素材的远端数据库存储规范

## 基本规则

正式工作台的作品以远端 MySQL 为唯一权威数据源。作品基本信息、节点草稿和产物、选角、任务及相关工作区信息保存在 `workspace_document`；Agent 运行、派发、画面生成和素材元数据保存在相应业务表。上传的素材原件写入 `creator_media_content`，与 `media_file` 元数据在同一事务中提交；作品配音的清单和音轨存入 `creator_dub_run`、`creator_dub_audio`。共享声音角色继续使用 `voice_character`、`voice_audio`。

上传素材单文件最多 50 MB。素材原件和配音音轨保存 SHA-256，配音读取时校验；画面素材采用前也会校验。配音生成需要本地临时文件，远端存储成功后才视为持久化完成。本地目录、浏览器缓存或 H2 不能作为正式作品的唯一保存位置。隔离开发测试可显式开启本地数据库，不应连接或覆盖正式作品。

数据库连接失败必须向调用方报告，不能静默切换本地存储。工作区使用版本号防止并发覆盖；新建作品及相关文件应使用唯一 ID。跨主机操作时，配音运行中的进程和临时文件不可跨机续跑：完成的音轨可跨机读取，中断的任务须重新处理。LangGraph 的运行时检查点目前仍是本机 SQLite，它不是已交付作品的存储，也不支持跨机恢复执行中任务。

## 配置与启动

Windows 启动脚本默认使用 `model.local` 中现有的 `voice.database` 连接信息和 Windows 凭据管理器中的凭据引用，工作区与声音库连接同一个 MySQL 数据库。`model.local` 不纳入 Git，文件只包含连接参数与凭据引用，不包含密码。连接也可由完整的 `CREATOR_DB_URL`、`CREATOR_DB_USER`、`CREATOR_DB_PASSWORD` 进程环境变量覆盖；只提供部分变量会启动失败。作品配音还需要通过 `voice.database` 或 `CREATOR_VOICE_DB_*` 配置同一远端数据库；若缺少该配置，配音接口会明确报错，不会退回本地文件。密码仅传给后端，不传给浏览器。数据库使用 TLS；目前无独立 CA 配置时只保证传输加密，不能验证服务端身份，正式部署应配置可信证书并验证主机名。

先完成后端构建、前端依赖安装和运行时安装，再运行 `scripts/start-local.ps1`。脚本会选择 MySQL profile；远端不可用时启动失败，不转到本地 H2。`scripts/start-local-deepseek.ps1` 同样使用远端数据库，真实模型仍须按该脚本要求启用。其他主机需要自行配置连接参数和本机凭据；不能从仓库获取凭据。启动后从工作台检查作品和素材，停止使用 `scripts/stop-local.ps1`。

## 迁移、备份和维护

- 共享数据库中还可能有其他项目的数据，只对本项目表做非破坏性、可重复的结构迁移；不得清库、覆盖其他表或以示例数据重置工作区。
- 从旧主机迁移前停止写入并备份 MySQL、旧 H2、素材原件、配音文件及必要的运行时检查点。对工作区、任务、配音清单和音轨逐项对账，按 ID 及内容识别冲突；不能无条件覆盖同 ID 项目。
- 必须同时迁移素材元数据和原件；只迁移作品 JSON 会造成图片、视频或音频无法打开。迁移后核对数量、引用、字节长度和 SHA-256，再使用另一台主机执行读取验证；旧副本保留至恢复演练通过。
- 数据库本身不是备份。应定期进行可恢复备份并演练恢复，包括业务表、素材、音轨与声音角色；密钥独立保存。大文件入库会增加数据库容量、传输内存及备份时间，容量增长后需评估对象存储方案，并先修改本规范和迁移计划。
- 模型配置仍须按 `model.local` 规则管理；当前旧版工作区中的模型档案尚未完成迁移，不可清空。

本规范约束后续功能，不代表所有规划中的生成、发布、跨机续跑功能已经实现。
